# beads-ui — Mike's fork

This is `mikez93/beads-ui`, a fork of `mantoni/beads-ui`, the web UI for the Beads CLI. It is the primary web UI in Mike's setup, replacing bead-kanban. The fork owns fixes that upstream has not shipped and sends generic fixes upstream when authorized. The sibling Intel Vault guide is at `../agentic-coding-resources/intel-vault/tools/ecosystems/beads-ecosystem/beads-ui/README.md`.

## Project workflow

Use `.specs/` for active PRDs and phase plans; create or update one before nontrivial implementation. Capture goals, scope, file-level approach, checks and completion criteria. Use `npm run all` for lint, typecheck, tests and formatting checks; individual commands are in `package.json`. Tests use Vitest; run focused tests for changed behavior, then the full suite as appropriate.

The app is an ESM Lit-html client and Node.js server. Main areas are `app/` (state, routing, views and utilities), `server/` (HTTP/WebSocket, Beads adapters and CLI), `bin/`, `scripts/`, `docs/` and `.specs/`. Keep UI and server behavior aligned, especially workspace selection and Beads CLI arguments.

## Conventions

Follow upstream-compatible conventions: JavaScript ESM, strict JSDoc checking, `.ts` files for types only, and Node 22 or newer. Use PascalCase for types/classes, camelCase for functions, lower snake case for other variables, and kebab-case paths. Add JSDoc parameter types and non-obvious return types; annotate mutable or empty collections. Use braces for control flow and explicit narrowing for nullable values.

Keep tests focused on one behavior, named with active verbs and structured setup, execution, assertion. Co-locate tests with implementation. Fix a failing test or underlying defect; do not change implementation merely to satisfy a test. The `debug` package uses `beads-ui:*` namespaces; browser debugging uses `localStorage.debug`, server debugging uses `DEBUG`.

## Upstream and design

`origin` is Mike's fork and `upstream` is `mantoni/beads-ui`. We pull from `upstream/main` periodically and rebase our fixes on top with `git fetch upstream` followed by `git rebase upstream/main`; conflicts are most likely in `server/list-adapters.js` and `app/views/workspace-picker.js`. Issue #58's issues-view cap at 50 and “Status: Any” hiding closed issues has been patched locally in `server/list-adapters.js` for months, so preserve that behavior during sync. `CHANGES.md` is generated by `@studio/changes`; do not edit it manually. Use conventional commit prefixes and reference an issue or spec where relevant.

Before proposing an upstream PR, check current upstream state and confirm the fix is generic. Mike's instruction is required before publishing a PR or pushing externally. Keep changes focused and include the upstream issue when one exists.

Windows support is limited: URL opening uses `cmd /c start`, and daemon shutdown depends on Node process-kill behavior. The UI complements `bd`; it does not replace it. Aim for a fast, sharp, technical, keyboard-first interface: dense but polished, restrained, and clear about state. Read `.impeccable.md` for visual changes.
